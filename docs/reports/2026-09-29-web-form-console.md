# Web管理画面・フォーム配布・投稿削除の改修レポート

## 実装

- ダイアログとWeb画面で同じHTML・処理を共用。1プロジェクト1運用、Webは本人限定。独立GASの初回画面でJSTの運用スプシを新規作成できる。
- クラスごとのフォーム複製・非公開化・回答先設定、名前／評価／コメント／状態列の事前準備、参照元と対応表の登録。
- 名前はClassroom生徒一覧のコースID＋メールで照合。回答トリガー、取り込み前の追補、手動補完。未照合は空欄のまま、手入力名と採点は保持。
- 回答者範囲と確認済みメール収集を検査し、確認操作で資料を投稿。受付開始・停止は返却停止と別。投稿結果不明でも受付停止できる。
- 資料と新規個別返却のIDを保存し、本文・投稿ID・日時を確認して削除。回答・採点・送信済み状態は保持。資料は明示的な再投稿が可能。返却履歴は50件ずつ表示。
- 紐付きスプシの次期間コピーは設定・クラス・生徒のみ再利用。コピー先から回答・送信待ち・旧フォーム参照・作成履歴を除き、元運用を保持。初期化結果不明時は再初期化しない。
- 配置対象は既存5ファイル。READMEと手動導入手順を更新。

## 残る確認・制約

1. **実フォーム作成→回答→採点→返却、資料・返却の実削除は未確認。** 検証クラス名「テストクラス」は受領済み。ひな形と保存先は未指定のため、専用資源の作成・資料投稿・削除の許可を質問中。実際の操作はしていない。
2. Forms APIの有効化、追加Google権限、複製後の回答者権限と回答前のタブ生成を実機で確認する。学校の回答制限自体はユーザー確認済み。
3. 実GASでの500件所要時間は未計測。投稿ID記録は1件につき履歴書込とflushを追加する。**過去レポートの1005 flushは、新しい5ファイル構成全体の測定ではない。** 履歴の全件再読込は実行内キャッシュで抑える。時間を区切る自動再開は未実装。再実行時は送信済み・送信確認待ちを除外。
4. 削除対象はこの版でIDを記録した投稿。別GASプロジェクトや旧版のID不明投稿は対象外。削除結果不明でAPIが404を返す場合は権限喪失と区別できないため、自動で削除済みにはしない。
5. 独立GASのWeb新規作成方式は、次期間に別GASの5ファイル配置とJSON再利用が必要。スクリプト込みの画面内コピーは紐付きスプシ方式に限定。集中した複数運用の同時制御は対象外。
6. グループ単位の回答権限、資料のトピック指定、評価集計、scoring-tool連携は今回含めない。基礎科目と化学は別運用。

次は専用検証資源で1クラス・1回答の通し確認を優先。実測で必要な場合だけ時間分割を検討する。
