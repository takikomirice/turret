# フォーム管理の初期準備と管理列への統合

## 変更内容

- 「必要なシートを準備」でフォーム管理を含む7シートを準備する。既存のフォーム管理記録は保持する。
- 採点保存の完了状態と重複回答の採用判断を、回答タブの1列 `管理` にまとめる。最終2列は `管理`、設定した送信状態列の順序とする。
- `_scoring_saves`、`_scoring_decisions` を新規作成しない。旧記録は初期準備時に移行し、読み戻し確認後に旧2シートを削除する。
- Apps Scriptの配置対象は従来の5ファイル。今回の実行コード変更はCode.gsとAdministration.gs。管理画面の説明を変更する別作業と編集範囲を分けた。

## データと失敗時の扱い

- 管理セルはJSONで、`v:1`、`save.state`（pending / complete）、`duplicate`（group / fingerprint / revision / choice）を保持する。採点内容は従来の採点列へ保存する。
- 保存前にpendingを永続化し、採点の書き込み後にcompleteを記録する。管理セルの更新ではもう一方の記録を保持し、まとめて書き込み・読み戻し確認する。
- 複数スプレッドシートにまたがる採用判断は全回答の世代と内容を照合する。一部だけ書き込まれた場合や新しい回答が増えた場合は、グループ全体を未確定として返却を止める。
- 列移動前の見出し順と採点設定の対応を管理列見出しのメモへ保存し、読み戻してから移動する。既存の列記号指定・移動前に開いた下書き・旧重複判断の照合値を維持する。空見出しや同名見出しも照合対象に含める。
- 旧記録の対象が見つからない、JSONが壊れている、保存結果が一致しない場合は移行を停止し、旧シートを保持する。再実行では新方式で保存済みの情報を古い情報へ戻さない。
- 管理セルは採点比較の回答項目に表示しない。管理は予約名として、設問名・採点出力先・返信本文の取り込み元に使えない。
- フォーム更新で回答の残る削除済み設問列を保持し、その後ろに管理と送信状態を配置する。物理的な行の並べ替え・削除を行わない従来の制約は維持する。
