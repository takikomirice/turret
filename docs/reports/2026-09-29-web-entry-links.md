# Web管理画面の入口・シート直リンクの修正

## 原因

- スプシメニューの`ScriptApp.getService().getUrl()`が、現在のデプロイ一覧にないURLを返していた。利用者が提示したURLで「ページが見つかりません」を再現した。
- 同じ確認用プロジェクトの公開Web画面内で実行すると、現在開いている有効な公開URLが返ることを読み取り診断で確認した。Google内部で古いURLが返る理由までは特定していない。
- Web画面のシートボタンはRPC完了後に画面下へリンクを表示する実装だった。対象タブへ移動するまでに追加操作が必要だった。

## 修正

- 本人確認済みの公開Web画面を開いた際に、公開URLとプロジェクトIDを`TURRET_WEB_ENTRY`へ記録。メニューはこの記録を使用する。スプシ側の未確認URLを直接案内しない。
- 開発用`/dev`、別プロジェクトの記録、破損した記録は公開リンクに使用しない。初回はデプロイ画面のURLを一度開くよう案内する。複数の公開デプロイがある場合は最後に開いたものを記録する。
- 管理画面データに各シートの`#gid=...`付きURLを追加。Web画面のクラス一覧・生徒一覧・対応表・評価／送信／エラーへの個別操作は直接リンクにする。存在しないシートは無効表示。スプシ内のダイアログは同じスプシでのタブ切り替えを維持する。
- 以前の希望どおり、データ整理の「シートを確認・編集」はWeb版ではスプシ全体へのボタン1つを維持する。
- 追加API権限なし。配置ファイルは5のまま。README・開発手順を更新。

## 検証

- `node --test`：324件成功。古いURLを返すメニュー実行、公開Web実行、開発用URL、別プロジェクト、未登録、本人以外のアクセス、gid=0、未作成シート、スプシ内ダイアログの経路を確認。
- 更新前の5ファイルを`.local/remote-backup/20260929-links-before`へ退避し、開始時HEADと一致することを確認。
- 本人限定の確認用Webアプリをバージョン11へ更新。一時的なURL診断分岐は最終版から除去済み。
- 公開Web画面を開き、URL登録処理を実行して正常表示を確認。クラス一覧はgid=519716503、生徒一覧はgid=848269423の直接リンクとして表示。クラス一覧のリンク先URLを開き、クラス名の見出しと該当タブへの遷移を確認。
- メニュー小窓の再表示・リンククリックの実機操作は、利用可能なUI操作APIの制約で未実施。小窓が記録済みURLを使う処理は自動テストで確認。開いている旧小窓を閉じ、メニューから再表示して利用する。
- 設定内容・生徒への投稿・メール送信・自動実行トリガーは変更していない。
