# 配付済みフォームの更新と回答列の整理

## 操作

- 「資料を投稿」の各フォームに「ひな形から更新」を追加。同画面の「すべてのフォームを更新」で、準備済みの管理対象をまとめて処理できる。
- 作成時に登録したひな形の質問・説明を、既存フォームへ反映する。フォームID・回答先・Classroom投稿・クラス別タイトル・公開範囲は維持する。
- 確認画面には質問の追加・変更・削除、更新後の列順、残す列、削除する空列を表示する。
- 回答列は「先頭のシステム列 → 現在の質問順 → 名前・追加列・送信状態 → その他の手入力列 → 削除済み質問の履歴列」に整理する。質問削除はGoogle Forms本体の回答履歴にも影響するが、回答シートの既存値は保持する。
- 削除済み質問の列は、見出しを除いて値・数式・メモがない場合だけ削除する。0、false、空白文字、表示結果が空の数式も保持する。列全体を移動し、回答行や管理列の値を書き直さない。
- 「フォームを準備」の追加列に上下ボタンを追加。列名とプルダウンの選択肢を一緒に移動する。新規作成時の配置順に適用され、既存フォームの追加列設定を変更する操作ではない。

## 整合性と再開

- 新規複製時にひな形と配付先の項目ID・質問IDの対応を記録。更新は既存質問のIDを維持する。旧記録はID、または一意な質問名と種類で対応を確認する。質問名を変更しても、設定が参照する既存の回答列名は維持する。
- 同名列との衝突、質問の種類変更、回答先の変更、テスト設定の不一致を事前に検出する。種類変更は別の質問として追加する。更新の対応範囲は下記を参照。
- 質問の追加だけでは本文への差し込みは増えない。「列と項目」と「メッセージ」で追加項目を登録する。削除した質問を取り込み設定で使用していた場合は、設定も見直す必要がある。
- 確認後にフォームや列構成が変わった場合は再確認する。FormAppの各変更前後に項目・設定を読み戻し、保存した更新記録と照合する。原子的なリビジョン指定はできないため、更新中はひな形・配付先・回答シートを手動編集しない。
- 更新記録を保存してから回答受付を一時停止する。フォームの反映結果と回答列を読み戻して確認し、完了後に元の受付状態へ戻す。
- 通信切断・シート反映待ち・列移動失敗時は「更新を再開」で照合する。更新途中の取り込み・本文生成・送信・リマインドは停止する。更新中に「受付停止」を選んだ場合は再開後も停止を維持する。
- GAS配置対象は従来の5ファイル。ローカルテスト・検証用資料は配置対象に含めない。

## Forms APIを使わない構成

- 初回はDriveの高度なサービスでひな形を複製し、FormAppで回答先・公開状態を設定する。Google Forms REST APIは呼ばず、`forms.body.readonly` と不要になった外部接続スコープを削除した。標準Cloudプロジェクトの新規作成・切り替えは不要。
- 配付後の更新もFormAppを使用し、既存の質問ID・フォームURL・回答先・投稿を維持する。新規質問のIDは作成後に記録する。通信応答が失われた場合も作成結果を照合し、同じ質問を重ねて作らない。
- 対応する更新は、記述・選択式・尺度・グリッド・日付・時刻・時間・セクションの追加、編集、削除、移動。セクション分岐は配付先の項目IDへ変換する。
- 採点用のテスト形式、動画、ファイルアップロードを含むフォームの自動更新は、取得できない設定を失わないよう事前に停止する。初回の複製・配付は利用可能。画像の追加・差し替えも自動更新の対象外とし、既存画像は維持する。
- 回答の検証ルール、質問内・選択肢の画像、シャッフル、テーマは同期しない。既存項目の設定は保持するが、新規項目では必要に応じて各フォームで設定する。確認画面にも同期対象外の説明を表示する。
- FormAppで判定できるのはメール収集の有効・無効まで。「確認済み」か「回答者からの入力」かは判定できないため、フォーム画面での確認を必須とした。準備時のチェックと投稿・受付再開時の確認を設け、ひな形URLを変えたときはチェックを解除する。
- Classroom資料操作の権限は、公開状態や投稿処理の記録を変える前に確認する。Googleが返す権限情報やキーの順序の違いだけで確認が無効にならないよう正規化する。
