# 採点処理の軽量化と不具合修正

対象はturretへ統合済みの採点処理。比較元は `2864e4c`。単独版scoring_tool、main、v4.0.0の履歴は変更しない。

## 測定方法と結果

`pnpm bench:scoring` で500件・5,000件の架空回答を5シートへ分配し、1シートの初期表示と返却前の重複判定を測定する。各回答は10列で、長文回答と参考文3列を含む。同じ生徒の異なる授業日を使い、通常ケースでは重複なし。既存のGASコードを代替サービスで実行し、取得セル数・GAS呼び出し数・JSONのUTF-8バイト数を数える。

5,000件中、選択中シートの1,000件を表示する場合:

| 指標 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 初期応答JSON | 8,229,068 bytes | 1,705,395 bytes |
| 読み取りセル数 | 106,200 | 50,080 |
| スプシを開く呼び出し | 5 | 1 |
| シート一覧取得 | 10 | 1 |
| タイムゾーン取得 | 5,000 | 5 |
| 指紋計算 | 10,001 | 1 |
| 返却前の判定: 読み取りセル数 | 100,180 | 50,080 |
| 返却前の判定: 指紋計算 | 10,000 | 0 |

初期応答は約79%、読み取りセル数は約53%削減。500件でも応答は823,634→171,683 bytes、セル数は10,800→5,080となった。Node上の時間は環境依存の参考値で、学校環境のGAS待ち時間・通信時間や実行上限への余裕を保証しない。

比較は必要時に対象グループの本文を取得する。101件の同日再提出でも、表示値の取得は対象シートごとに1回（別途、対応表を1回）とする。シートをまたぐ重複を見落とさないため、判定そのものは全対象の回答を読む。計算量が回答件数に比例する点は残る。

## 実装

- 同じGAS呼び出し内でスプシ、シート一覧、回答値を共有。呼び出しをまたぐキャッシュは使わず、追加回答・設定変更・採用判断の反映を維持。
- 通常の初期表示と返却判定では全答案の本文・表示値を組み立てない。指紋は重複グループだけ計算し、既存の採用記録と互換にする。
- 比較本文は最新値を取得し、採用結果と表示更新を1回のRPCで返す。既存APIの完全な応答形式は既定として残し、採点画面が軽量形式を明示的に選ぶ。
- テンプレートの条件表示と自動講評で、取得済みの同じルールを共有する。入力時の評価では、既に確定した出力先や使用しない出力先の条件評価を省く。
- 旧単独版の空の接続処理・復元処理と未使用の状態を除去。配置は5ファイル、追加API・Cloud設定変更なし。

## 修正した不具合

- 再評価直後のシート切替で、古い回答の下書きを新しいシートのキーへ保存する問題。
- 明示的な再評価で未保存状態にならず、生成した講評を行移動で失う問題。
- ルール取得中・通信失敗時に講評を空欄で上書きする問題。取得を再試行でき、手入力後の遅延応答も手入力を上書きしない。
- 第1枠の再評価に二重のイベント処理があり、第2・第3枠も上書きする問題。
- ルール取得待ちなどで下書きを保持できていない場合、画面を閉じる際の警告を出さない問題。
- 比較を閉じた後の遅延応答、表示中回答が比較グループから外れた後の採用を防止。

## 検証

`pnpm test` で511件成功。正常系に加え、通信失敗、遅延応答、下書きの保存先、手入力保護、比較の再取得、101件の重複、一括読み取り数、旧形式との指紋・返却可否の一致、別ユーザー拒否を確認した。独立レビューの比較I/Oとグループ所属確認の指摘を修正済み。

実運用で蓄積した大量データを使うGAS実行時間や、生徒へのClassroom返却は、このベンチマークの検証対象に含めない。

確認用GASとChromeでは、専用の架空回答3件を作成し、0点入力→自動講評→まとめて保存→比較に保存済み評価を表示→後の回答を採用→比較先3行目へ移動を確認。比較を開き直しても採用チェックが保持された。終了後、専用シート・対応表・テンプレート・内部記録を削除し、採点設定を元へ復元した。Classroom投稿数は0件。一時検証コードは配置対象に残さない。
