# v6.1.0 — フォーム準備・資料投稿の整理と名簿照合の改善

フォームの準備、評価・コメント列の追加、資料投稿を分け、複数クラスへの設定と投稿をまとめて操作できるようにしました。名簿の除外指定と送信直前の照合を追加し、採点画面から回答の名前を補完できます。

## 主な変更

- **フォーム準備を2段階に整理**：「フォームを準備」で作成と回答先の接続を行い、「評価・コメント列」で採点用の列を追加します。回答先URL・回答タブの接頭文字は自動設定し、既存接続は保持します。保存済みの列名は一覧に表示し、追加せず設定内容だけを確認できます。
- **作成済みフォームの設定編集**：「フォームを準備」でフォーム名・回答許可先・クラス表記の変更項目だけを、選んだ複数クラスへ適用できます。回答タブ名・既存回答・採点結果・投稿IDは保持します。途中失敗からの再開と、受付終了後の再開防止にも対応します。
- **資料投稿の一括設定と個別操作**：投稿タイトル・投稿文は「資料を投稿」で登録します。「一括設定」の文面保存・即時投稿・公開予約・受付終了予約と、各フォームの「個別登録」「個別操作」に整理しました。新規フォームは文面保存後に投稿・予約でき、未保存の入力や開閉状態を保持します。投稿済み・予約済みの文面反映では、同じ投稿IDと公開状態・予約日時を保持します。
- **名簿の整列・除外・送信先再照合**：取得時はクラス名の数字順、生徒はクラス別・出席番号順に整列します。「生徒一覧」の `除外(1)` に `1` を入れると、再取得後も除外状態を保持します。除外は名前補完・送信準備・成績出力にも反映します。送信直前に名簿を再照合し、削除・除外・studentId変更を検出した場合は投稿を止めます。手編集後の並べ替えは一覧シートのフィルターから行います。
- **採点画面の「名前を反映」**：「採点テンプレ」の右側から、選択中の管理フォーム回答タブ全体の空欄の名前を補完します。クラス・メールで名簿と照合し、既存名・数式・採点値を保持します。未保存の採点入力も再読込後に保持します。
- **設定とプレビューの改善**：列と差し込み項目を通常のプルダウンで選択でき、本文編集中のプレビューを自動更新します。通知先が不要な場合は「通知しない」を保存して確認できます。スプレッドシートのメニュー名は「操作画面」になりました。
- **不具合修正**：複数クラスのフォーム準備プレビュー、学校ドメイン付きWebアプリURLの登録、日本語の回答先未設定エラー、フォーム回答テーブル内の管理列・送信状態列の移動を修正しました。

## v6.0.0からの更新

1. 運用スプレッドシートとApps Scriptのコードをバックアップしてください。
2. 配置対象は `Code.gs`、`Administration.gs`、`Setting.html`、`Scoring.html`、`appsscript.json` の5ファイルです。今回変更した製品コードは前の4ファイルです。既存Webアプリを新しいバージョンへ更新し、画面を開き直してください。
3. スプレッドシートを再読み込みし、「操作画面」メニューを確認してください。「シートを準備」または生徒一覧の再取得で `除外(1)` 列を用意できます。旧6列・7列の名簿は読み取り互換を維持します。除外を解除するときは該当セルを空欄に戻してください。
4. 新規フォームは準備後に評価・コメント列を追加し、「資料を投稿」で文面を保存してから投稿・予約してください。従来の準備画面で保存済みの投稿設定は引き続き使用できます。

追加Cloudプロジェクト・追加APIの有効化は不要です。メール収集の「確認済み」は、ひな形フォームで初回に手動設定してください。FormAppのメール収集オン・オフだけでは方式を判定しません。GitHubリリースの作成だけでは、利用中のApps ScriptやWebデプロイは更新されません。
