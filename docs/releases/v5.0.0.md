# v5.0.0 — 採点画面と返却運用の統合

フォーム準備・配布を含む管理画面に、回答の採点、重複回答の確認、採点テンプレート編集、既存の日次返却処理との連携を統合しました。

## 主な変更

- **独立した採点画面**：回答内容を確認しながら5枠の点数と3枠の講評を入力できます。ルールによる講評生成、手修正、キーボード操作、ブラウザー内の下書きとシートへの自動保存に対応します。
- **重複回答の確認**：同じメールアドレス・クラス・授業日の回答を比較し、返却対象を選べます。判断が必要な回答は自動返却を保留します。
- **採点テンプレート編集**：条件表を画面とスプレッドシートの両方から編集できます。CSVの貼り付け・読み込み、検査、試算、テンプレートパックの入出力に対応します。
- **既存返却処理との連携**：採点保存だけでは生徒へ送信しません。採点済み判定と既存の日次処理を使って返却します。採点内容は送信準備へ反映され、返却済みの投稿は保持されます。
- **保存状態の管理**：採点保存の完了状態と重複回答の採用判断を回答タブの `管理` 列にまとめます。既存の送信状態列とともに読み書きし、途中失敗や設定変更時には返却を保留します。
- **運用の改善**：管理画面の説明を整理し、フォーム・採点・テンプレート編集の画面間を移動しやすくしました。フォーム準備、予約運用、日次処理の信頼性改善も含みます。

## v4.0.0 からの更新

1. 運用スプレッドシートとApps Scriptのコードをバックアップしてください。
2. `Code.gs`、`Administration.gs`、`Setting.html`、`Scoring.html`、`appsscript.json` の5ファイルを反映してください。旧 `Automation.gs` は配置しません。手動での貼り付け更新にも対応します。
3. Webアプリを新しいバージョンへデプロイしてください。GitHubリリースだけでは、利用中のApps Scriptは更新されません。
4. 管理画面の「必要なシートを準備」を実行し、画面の案内に従って既存の採点記録を移行してください。移行が確認できない場合は旧記録を削除せず、案内に従って復旧してください。
5. 採点設定と返却対象を確認し、架空データで動作を確かめてから運用してください。採点保存だけでは生徒へ送信しません。

追加のGoogle CloudプロジェクトやGoogle Forms APIは不要です。学校環境のCloud制約と手動導入については[README](../README.md)を参照してください。
