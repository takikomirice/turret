# 採点テンプレ統合 Implementation Plan

> 実装方法: 同じ作業ブランチで主担当が統合実装し、最後に独立した差分レビューを行う。ユーザーは実装を明示承認済み。形式的な計画承認で停止しない。

**Goal:** 採点テンプレ1枚を日本語の表としてシートと画面の双方から編集し、5条件・3出力、検査、試算、AI向け説明、個別修正を提供する。

**Architecture:** Code.gsに保存・条件解釈・検査を集約。Scoring.htmlの既存式作成の入口とサイドバーを表編集へ置き換え、採点時は変換済みルールを既存のローカル評価経路へ渡す。出力1〜3は常に位置を固定する。

**Tech Stack:** GAS標準SpreadsheetApp、HtmlService、既存のブラウザJavaScript、node:test。

**Spec:** この会話で承認された①④。枠は1〜5、出力は1〜3。各枠の有限な点数一覧はテンプレート単位。空条件は指定なし、空行は無視、出力空欄はその出力を指定しない。上から出力ごとに最初の一致を採用。旧形式の移行と枠同士の計算条件は不要。未採点と0は区別する。

## Global Constraints

- GAS配置対象は既存5ファイル。追加API・Cloud設定変更なし。
- 学校の回答・既存シートを削除しない。旧ルールシートは新方式では参照しない。
- 採点結果の手直し・枠ごとの再評価・未保存保護を維持。
- シート全体の版を比較し、画面からの保存はロック中に読み直す。競合時は入力保持。
- シートの主要列はテンプレート名、枠1〜5、出力1〜3。右側は使用する、採点画面に表示、枠1〜5の点数、テンプレートを使用。点数と全体有効設定はテンプレートの先頭行に保存。
- 本文は通常の文章と {枠1}〜{枠5}・{合計} の差し込み。式・HTMLとして評価しない。

## Review Focus

- 出力2だけを使うテンプレートでも出力1の保存先へずれない。
- 不正条件・未採点・0・全条件空欄・出力0・出力空欄を区別。
- 条件が同じでも担当する出力が異なる場合は重複にしない。
- 行削除、シート編集、同時保存、数式文字列、保存途中失敗を検査。
- 検査量が大きい場合は未検証範囲を明示し、完全検査済みと扱わない。
