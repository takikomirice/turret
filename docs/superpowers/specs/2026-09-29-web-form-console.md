# Web管理画面とフォーム配布

合意済みの会話を実装へ反映する。今回は1つのGASプロジェクトが1つの運用スプレッドシートを管理する。基礎科目と化学、次の期間は別運用。複数運用の集中実行は対象外。

- 既存のダイアログとWeb画面は同じHTML・サーバー処理を使う。スプシは明示IDで開けるようにする。Webは管理者本人限定でデプロイする。
- 初回のWeb画面から空の運用スプシを作れる。既存の紐付きスプシはメニューから接続する。接続先を入力任せに切り替えない。
- 次期間は既存の紐付きスプシを複製して設定・クラス・生徒だけ再利用する。回答・送信待ち・フォーム参照・作成履歴は複製先から除く。元ファイルは変更しない。複製先のWebデプロイと自動実行は本人が別途開始する。
- 同期対象クラスごとにひな形フォームを複製し、同じ運用スプシへ回答を集約。名前・評価・コメント・状態列を回答前に準備。名前はClassroom生徒一覧のコースID＋メールで補完する。
- 最初は準備だけを行う。本人メール収集・回答者範囲を検証した後、確認画面から「資料」を投稿。学校ドメイン／個人検証用の明示メールを扱い、誰でも回答可能な状態を許可しない。
- 作成・投稿・削除は履歴とIDを保存。結果不明時は自動再作成・再投稿しない。既知IDの操作は状態を再照合できる。
- 投稿削除はこの運用で記録した資料・新規個別返却投稿のみ。対象を表示し確認後に削除。回答・採点・フォームは削除しない。返却投稿削除でも送信状態を未送信へ戻さない。旧投稿はID不明なので対象外。
- 回答受付停止は日次返却停止と別。学校で確認済みの制限を一般的な未解決事項として再質問しない。
- 配置は既存5ファイル。ローカルテスト・個人環境で検証、外部への投稿・削除の実機テストは具体的な対象を確認して実施する。

## 検証
既存テストの回帰、Webの対象固定、コピー隔離、クラス別作成、部分失敗と二重操作、学校／個人の権限検査、名前照合、資料／返却の削除、画面操作を検証する。実機未確認は完了と報告しない。
