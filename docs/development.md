# 開発・画面確認手順（Windows）

ローカルで編集・テストし、確認用のコンテナバインドApps Scriptへ同期した後、Chromeで確認します。管理画面はWeb版のみです。下記の本人限定デプロイを行います。

## Web管理画面の導入（2026-09-29）

配置対象は引き続き5ファイルです。claspが使えない環境ではApps Scriptエディタへ同名で貼り付けてください。

1. `appsscript.json`を含む5ファイルを更新。高度なサービスに既存Classroom v1とDrive v3を設定する。
2. Google Forms APIの有効化・標準Cloudプロジェクトの新規作成は不要。フォーム操作はGAS標準のFormAppを使用する。ひな形の「設定 → 回答 → メールアドレスを収集する」を「確認済み」にし、管理画面の確認欄へチェックする。メール収集の有効・無効は自動確認するが、収集方式はFormAppでは判定できない。
3. 既存の確認用スプシのメニュー「管理画面を開く」を実行する。追加のGoogle認証は本人が行う。
   - フォーム操作で権限不足になる場合は、Apps Scriptエディタで `authorizeFormIntegration` を選んで実行し、Forms・Drive・Classroom資料操作の不足権限を承認する。この関数はフォーム作成・投稿・シート更新を行わない。承認後にWeb画面の操作を再実行する。
   - `appsscript.json` はForms・Drive・Classroomなどの必要スコープを明示する。Forms REST用の `forms.body.readonly` は使用しない。

4. Apps ScriptでWebアプリをデプロイする。実行ユーザーは自分、アクセスは自分のみ。マニフェストにも同じ既定値を指定している。URLを生徒と共有しない。
5. デプロイ画面のWeb URLを一度開く（メニュー用URLを内部登録）。従来の設定・クラス取得・シートリンク・フォーム管理を確認する。接続した運用スプシのデータが表示されることを確認する。
6. テスト用フォーム・フォルダと検証クラスを指定。準備だけでは公開されず、明示的な資料投稿で公開されること、回答→名前→採点→返却、受付停止、資料・返却の削除を検証する。実生徒へのテスト投稿をしない。
7. 次期間への複製は元のスプシを保持し、複製先に回答・送信待ち・旧フォーム参照・作成履歴がないことを確認。複製先でWebを接続し、別途デプロイする。

独立GASから空のスプシを作成した場合は1プロジェクト1運用の接続を固定します。次期間用に別GASを用意する方式です。集中した複数運用の切替画面は今回含めません。

Webの開発確認は「デプロイ → デプロイをテスト」の `/dev` URLを使用可能です。公開用 `/exec` はコード保存だけでは更新されないため、新しい版にデプロイを更新します。[Webアプリ公式手順](https://developers.google.com/apps-script/guides/web)、[FormApp公式リファレンス](https://developers.google.com/apps-script/reference/forms/form-app)。
